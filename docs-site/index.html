Jelajah-In Progo

Dokumentasi teknis untuk memahami struktur, data, fitur, cara menjalankan, dan memublikasikan WebGIS wisata Kulon Progo.

Catatan penting tentang implementasi

Kode script.js yang diperiksa memuat data melalui fetch("/api/wisata") dan mengharapkan respons JSON. CSV tersedia di folder data/, tetapi kode yang diperiksa tidak membaca CSV secara langsung. Endpoint API harus disediakan oleh server agar data muncul; hosting statis saja tidak membuat endpoint ini otomatis.

⌖Peta interaktif

Leaflet dengan tile OpenStreetMap, marker, popup, dan zoom otomatis.

⌕Temukan lokasi

Pencarian teks, filter kategori, dan akses lokasi pengguna melalui browser.

▤Data CSV

Atribut destinasi menjadi sumber informasi tabel, statistik, dan detail.

Tujuan aplikasi

WebGIS ini menyajikan lokasi wisata melalui peta dan atribut destinasi. Antarmuka utama memiliki ringkasan statistik, daftar lokasi, peta, filter, kartu destinasi terpilih, detail destinasi, serta tautan rute Google Maps.

Getting Started

Pastikan struktur folder tetap dipertahankan, termasuk nama file CSV yang mengandung spasi. Untuk pengembangan lokal, gunakan server HTTP, bukan mengandalkan pembukaan file HTML langsung.

1. Ambil kode sumber

git clone https://github.com/aninditapawestria/jelajah-progo.git
cd jelajah-progo/Jelajah-In-Progo-WebGIS

2. Jalankan server lokal

Jika sudah ada backend yang menyediakan endpoint /api/wisata, jalankan backend tersebut sesuai konfigurasi proyek. Kode backend atau instruksi menjalankannya tidak dapat dipastikan dari tiga file frontend yang diperiksa.

Untuk hanya melihat layout HTML, buka folder dengan VS Code lalu gunakan ekstensi Live Server. Namun, tanpa API yang sesuai, data tabel/peta tidak akan termuat meskipun halaman terbuka.

# Contoh server statis Python untuk melihat tampilan saja
python -m http.server 8000
# Buka http://localhost:8000
Server statis bukan pengganti API

Contoh Python di atas hanya melayani file. Ia tidak mengubah CSV menjadi JSON dan tidak membuat rute /api/wisata. Gunakan backend yang sudah ada atau ubah mekanisme pemuatan data secara sengaja setelah memeriksa kebutuhan aplikasi.

Memahami kode

HTML — struktur halaman

index.html memuat bagian hero/navigasi, discover dan statistik, tabel lokasi, area peta, panel destinasi terpilih, detail destinasi, bagian tentang, dan footer. ID seperti map, locationTable, serta searchInput menjadi titik kait JavaScript.

<!-- Elemen peta yang dipakai Leaflet -->
<div id="map"></div>

<!-- File aplikasi -->
<script src="script.js"></script>

CSS — gaya dan responsivitas

style.css memakai CSS custom properties untuk warna, radius, dan bayangan. Breakpoint pada 950px, 720px, dan 500px mengubah navigasi, grid, panel peta, serta tombol detail untuk layar yang lebih kecil.

@media (max-width: 720px) {
  .map-layout {
    height: auto;
    grid-template-columns: 1fr;
  }
  .map-container { height: 560px; }
}

JavaScript — siklus aplikasi

Variabel global map, allData, markers, activeCategory, dan selectedData menyimpan keadaan aplikasi. Setelah DOM siap, aplikasi menginisialisasi peta, memuat data, lalu memasang event handler.

document.addEventListener("DOMContentLoaded", () => {
  initMap();
  loadData();
  setupEvents();
});

Fungsi penting lain: updateStatistics(), renderCategoryOverview(), renderFilters(), renderTable(), renderMarkers(), applyFilters(), selectDestination(), normalizeCategory(), markerColor(), dan escapeHtml().

Perhatikan perbedaan CSV dan kode

CSV yang diperiksa tidak memiliki kolom kabupaten, sedangkan fungsi detail mencoba membaca item.kabupaten dengan fallback teks “Kulon Progo”. CSV juga memiliki kolom foto, tetapi tidak terlihat dipakai untuk menampilkan foto pada detail. Beberapa baris memiliki nilai yang tidak seragam; validasi CSV/API perlu dilakukan di sisi sumber tanpa mengubah data diam-diam.

Kontrak data untuk frontend

Frontend mengharapkan /api/wisata mengembalikan array JSON berisi objek dengan nama properti yang cocok dengan kolom CSV, terutama koordinat numerik dan id yang stabil. Contoh bentuk data, bukan pengganti dataset:

[
  {
    "id": 1,
    "nama_wisata": "Nama dari CSV",
    "kategori_wisata": "Wisata Alam",
    "latitude": -7.64,
    "longitude": 110.14
  }
]

Fitur aplikasi sesuai kode

Peta interaktif, marker, dan popup

Leaflet memulai peta di sekitar koordinat [-7.75, 110.15] pada zoom 11, memakai tile OpenStreetMap, dan membuat circleMarker dari latitude/longitude. Warna marker ditentukan oleh kategori. Klik marker membuka popup dan menyinkronkan panel destinasi terpilih.

Pencarian dan filter kategori

Pencarian menguji kata kunci terhadap nama, kategori, kecamatan, desa, alamat, dan deskripsi. Filter kategori dan pencarian diterapkan bersamaan. Daftar hasil pencarian menampilkan hingga delapan item; memilih hasil akan memusatkan peta dan membuka popup jika marker masih tersedia.

Tabel wisata

Tabel menampilkan maksimal 12 baris dari hasil yang sedang diberikan ke fungsi render, sementara label hitungan menggunakan jumlah data hasil filter. Tombol pada baris memilih destinasi, menggeser peta ke zoom 15, lalu menggulir halaman ke area peta.

Statistik

Statistik menghitung jumlah baris, jumlah kecamatan unik, jumlah kategori unik, dan jumlah titik yang diasumsikan sama dengan jumlah baris. Kode tidak memvalidasi koordinat untuk menghitung ulang jumlah titik valid.

Detail destinasi

Panel detail menampilkan nama, wilayah, kategori, deskripsi, jam operasional, tiket, koordinat, media sosial, toilet, mushola, dan tempat makan. Informasi berasal dari objek data terpilih.

Rute Google Maps

Tombol rute membuka Google Maps Directions dengan koordinat destinasi sebagai tujuan. Kode tidak menentukan titik awal khusus; Google Maps menangani pemilihan titik awal/rute.

Lokasi pengguna

Tombol lokasi memakai navigator.geolocation untuk memusatkan peta ke posisi perangkat pada zoom 13. Browser dapat meminta izin dan umumnya memerlukan HTTPS atau localhost.

Keamanan keluaran

Fungsi escapeHtml() meng-escape karakter HTML pada sejumlah nilai sebelum dimasukkan ke template HTML. Pertahankan sanitasi saat mengembangkan fitur berbasis data.

Checklist debug cepat

  1. Buka DevTools → Console untuk pesan JavaScript.
  2. Buka Network → muat ulang → periksa permintaan /api/wisata, status, dan response body.
  3. Pastikan response berbentuk array JSON dan kolom penting konsisten.
  4. Uji koordinat numerik serta nilai kategori yang dipakai filter.
  5. Pastikan akses CDN tidak diblokir.

Deployment & publikasi

Publikasikan dokumentasi melalui GitHub Pages

  1. Commit folder docs-site/ ke branch repository, tanpa mengganti file WebGIS utama.
  2. Buka repository GitHub → Settings → Pages.
  3. Pada bagian Build and deployment, pilih Deploy from a branch.
  4. Pilih branch yang memuat perubahan dan folder /(root), lalu simpan. Jika Pages repository sudah memakai sumber deployment lain, jangan mengubahnya tanpa memahami situs yang sudah terbit.
  5. Setelah workflow Pages selesai, buka URL Pages repository lalu tambahkan /docs-site/ di akhir path.
Alternatif yang lebih rapi

Jika ingin URL dokumentasi menjadi root situs Pages, pindahkan isi folder dokumentasi ke folder docs/ lalu atur Pages untuk menerbitkan folder /docs, atau gunakan repository terpisah. Periksa konfigurasi Pages yang sekarang sebelum memilih opsi.

Publikasi aplikasi WebGIS berbeda dengan dokumentasi

GitHub Pages melayani file statis. Karena frontend yang diperiksa meminta /api/wisata, aplikasi lengkap tidak akan berfungsi di Pages kecuali data/API disediakan dengan cara yang kompatibel dengan hosting statis atau backend dideploy ke layanan yang mendukungnya. Jangan menganggap publikasi dokumentasi berarti API aplikasi ikut terpublikasi.

Checklist sebelum rilis

  • Semua link navigasi internal menuju ID section yang tersedia.
  • File CSS/JS menggunakan path relatif.
  • Uji tampilan desktop dan ponsel.
  • Pastikan repository Pages memakai branch/folder yang benar.
  • Uji URL produksi dan buka Console/Network untuk memeriksa error.
